# ME 配方表样板总成：深度规则与路线规划设计

## 1. 文档目的

本文定义 `ME 配方表样板总成` 的下一代动态样板生成模型。目标是在大型、深度魔改的 GT 配方池中，能够在不牺牲 AE2 合成语义与服务器稳定性的前提下，识别可执行配方、选择合理路线、避免循环，并把选中的配方精确交给所属多方块执行。

本文是实现规格，不是用户说明书。除非本文明确标记为“兼容模式”或“可配置”，实现必须采用保守行为：无法证明安全或可执行的配方不得生成动态样板。

## 2. 范围与约束

### 2.1 已确认的产品约束

1. **单目标样板**：一个动态样板只能向 AE2 声明一个目标产物。
2. **副产物可成为目标**：同一物理配方的任何确定性产物都可以被单独请求；请求副产物时，该副产物就是该动态样板的目标产物。
3. **隐藏的实际产物**：物理配方仍会产出全部结果，但除当前目标以外的产物不进入该样板的 AE2 输出列表。
4. **NC 物品令牌化**：所有可表示的非消耗物品输入都包装为可编程电路；AE2 消耗电路令牌，缓冲区解包后的原物品用于 GT 的非消耗匹配。
5. **复杂路线优先**：必须支持大型配方池中的多路线选择、物料形态转换、回收路线、化学合成路线、循环路线和服务器自定义规则。
6. **数据优先、扩展可编程**：绝大多数策略由数据规则包决定；无法由数据描述的模组特性通过 Java 适配器扩展，不得继续在核心路线代码中堆积硬编码特例。

### 2.2 非目标

1. 不把多个主产物或副产物同时写入同一个 `IPatternDetails`。
2. 不把随机产物按期望值伪装成确定性 AE2 输出。
3. 不承诺支持无法放入缓冲区或无法由当前多方块验证的任意第三方配方语义。
4. 不以无边界扫描或全图穷举换取路线最优性。

## 3. 当前系统基线

当前实现的主要入口是：

- `MetaTileEntityMERecipeMapPatternProvider`：注册多方块可暴露的 `RecipeMap`，缓存动态样板，并将 AE2 推送请求送入缓冲区。
- `DynamicRecipePatternRegistry`：按请求输出建立索引、编码 GT 配方、选择候选路线、处理递归恢复。
- `DynamicRecipePatternDetails`：向 AE2 表示动态样板输入与单一输出。
- `MetaTileEntityMEPatternProvider`：持有隔离缓冲区，当前只把缓冲区绑定到 `RecipeMap`。

现状已经具备懒索引、库存感知评分、多 RecipeMap 路由、缓存和递归恢复，但仍有以下结构性不足：

1. 路线优先级通过核心代码中的少数材料启发式实现，难以表达大型整合包规则。
2. 随机产物会被直接排除，未形成统一的输出安全策略。
3. NC 物品编码受数量和表示方式限制。
4. 缓冲区只绑定到 `RecipeMap`，同表同输入的多个配方可能在执行时命中非生成阶段选定的配方。
5. 控制器能力、配方属性、输出容量、路线规则和循环约束没有统一的可解释决策链。

## 4. 总体架构

```mermaid
flowchart LR
    A["AE2 请求目标"] --> B["Provider / Machine 上下文快照"]
    B --> C["RecipeMap 输出索引"]
    C --> D["GT 配方规范化"]
    D --> E["可执行性规则链"]
    E --> F["单目标化与输出策略"]
    F --> G["路线图求解与循环约束"]
    G --> H["候选排序 / Pareto 前沿"]
    H --> I["精确 RecipeBinding"]
    I --> J["AE2 动态样板"]
    J --> K["缓冲区精确执行验证"]
```

核心原则是将“找到某个输出的配方”拆分为以下独立问题：

1. 配方是否可以被无损或安全地表达为样板输入。
2. 该配方是否可由当前总成和所属多方块执行。
3. 针对本次目标产物，是否可以安全地向 AE2 承诺产出。
4. 在所有可行路线中，当前策略应选择或暴露哪几条。
5. 执行时是否仍能验证并命中生成时所选定的精确配方。

## 5. 核心数据模型

### 5.1 `NormalizedRecipe`

`NormalizedRecipe` 是从 GT `Recipe` 读取后、尚未面向任何请求目标的不可变快照。它包含：

| 字段 | 说明 |
| --- | --- |
| `recipeBinding` | 配方表标识、稳定配方指纹、配方表内容版本 |
| `itemInputs` / `fluidInputs` | 包含替代项、数量、NBT 与消耗语义的规范化输入 |
| `deterministicOutputs` | 所有确定性物品与流体结果 |
| `chancedOutputs` | 所有随机结果及概率信息，仅供规则和诊断使用 |
| `nonConsumableRequirements` | 已识别的 NC 物品要求 |
| `properties` | GT 内建及第三方 `RecipeProperty` 的规范化键值 |
| `category` | 配方分类、来源模组、RecipeMap 标签 |
| `executionFacts` | EUt、时长、并行限制、输出数量等执行事实 |

`NormalizedRecipe` 不允许因库存、玩家选择或本次请求而变化。它是索引、规则缓存和稳定指纹的基础。

### 5.2 `MachineCapabilityProfile`

`MachineCapabilityProfile` 表示本次动态样板提供者与其所属多方块的可执行能力。至少包括：

| 类别 | 示例 |
| --- | --- |
| 结构与网络 | 总成有效性、结构成型状态、维度、Provider ID、当前世界时间 |
| RecipeMap | 可路由的 RecipeMap、当前选择、映射能力、配方表标签 |
| 能源与速度 | 电压、可用功率、超频策略、并行能力、批处理能力 |
| 机器环境 | 线圈等级、热量、温度、洁净室、维护、消音器、研究状态 |
| 输入输出 | 缓冲区槽位、流体槽、物品/流体输出能力、禁止虚空策略 |
| 专属能力 | 聚变启动能、计算量、扫描、Fog 或其他第三方多方块能力 |
| 版本 | 控制器状态签名、能力适配器版本、规则版本 |

上下文快照必须是只读的，并可被异步 AE2 规划线程安全读取。需要访问世界或 TileEntity 的信息必须在主线程采样后进入快照，不得在异步规划中直接读取可变世界状态。

### 5.3 `TargetedRecipe`

`TargetedRecipe` 是一个 `NormalizedRecipe` 针对一个确定性目标输出生成的视图。

| 字段 | 说明 |
| --- | --- |
| `target` | 唯一向 AE2 声明的物品或流体键 |
| `targetAmount` | 对目标的净确定性产出 |
| `patternInputs` | 由 AE2 提供的物品、流体与电路令牌 |
| `hiddenActualOutputs` | 实际会产出但不声明给 AE2 的结果 |
| `binding` | 精确配方绑定 |
| `explanation` | 规则决策、路线标签、成本、拒绝或降级信息 |

同一物理配方若有三个确定性输出，可形成最多三个 `TargetedRecipe`。它们互不共享 AE2 输出记账，但共享同一个实际配方绑定和输入语义。

### 5.4 `RecipeBinding`

`RecipeBinding` 是动态样板和缓冲区之间的精确执行契约。建议字段：

```text
recipeMapId
recipeFingerprintVersion
recipeFingerprint
recipeMapContentVersion
targetKey
normalizationVersion
ruleSetVersion
```

配方指纹必须由规范化输入、确定性输出、随机输出、分类、属性、EUt、时长和稳定的注册序号共同构造。不得只使用 `Recipe.hashCode()`；哈希碰撞或配方重载后必须能检测到不一致。

## 6. 单目标产物策略

### 6.1 生成规则

1. 仅从 `deterministicOutputs` 中枚举可作为目标的输出。
2. 每次请求只生成匹配该请求键的一个 `TargetedRecipe`。
3. 样板的 `getOutputs()` 仅返回该目标输出。
4. `hiddenActualOutputs` 不可用于 AE2 自动依赖求解，也不可被当作已入库物料。
5. 所有实际输出仍必须参与机器输出容量、虚空策略、堵塞风险和路线代价判断。

### 6.2 随机产物策略

默认策略为 `DETERMINISTIC_ONLY`：

| 场景 | 默认行为 |
| --- | --- |
| 目标是确定性产物，配方同时有随机副产物 | 可生成，但随机副产物作为隐藏实际产物参与输出容量判断 |
| 目标是纯随机产物 | 拒绝生成，理由为 `CHANCED_TARGET_UNSAFE` |
| 随机产物带有可证明的保证下限 | 可由专用规则适配器声明为确定性下限后生成 |
| 管理员显式开启不安全期望值模式 | 仅作为实验性策略；必须在 GUI、日志和规则解释中明确标注 |

### 6.3 隐藏副产物的风险规则

隐藏产物不会进入 AE2 账本，因此必须有以下硬约束：

1. 多方块拥有足以接收全部实际输出的输出能力。
2. 输出不得因禁用虚空、满仓或过滤器而必然堵塞。
3. 对高价值或危险副产物可设置 `denyHiddenOutput` 规则。
4. 路线评分可对隐藏副产物造成的浪费、堵塞概率或清理成本施加惩罚。

## 7. NC 物品的可编程电路令牌

### 7.1 语义

对于一个 NC 物品输入 `X`：

1. 动态样板向 AE2 请求一个包装了 `X` 的可编程电路令牌 `Token(X)`。
2. AE2 按普通输入消耗 `Token(X)`，不生成返还物。
3. 样板总成接收后不把令牌插入物品缓冲区，而是解包其内部 `X`。
4. 解包后的 `X` 放入隔离缓冲区的虚拟电路/催化剂槽，GT 配方仍按其原始 NC 语义匹配。
5. 配方执行结束后，缓冲区中的 `X` 仅在本次任务缓冲区生命周期内保留；后续任务再次由 AE2 消耗令牌。

这意味着“默认可编程电路是消耗品”，而不是返回到 AE2 的工具或催化剂。

### 7.2 数量与替代项

| 输入场景 | 令牌化策略 |
| --- | --- |
| NC 物品数量为 1 | 一个包装电路令牌 |
| NC 物品数量为 N | 展开为 N 个独立令牌输入和 N 个虚拟槽位 |
| NC 物品有多个替代项 | 每个替代项生成对应包装令牌，AE2 选择的令牌决定实际解包物品 |
| 带 NBT 的 NC 物品 | 令牌必须保留完整 NBT，指纹也必须包含 NBT |
| 集成电路 | 与普通 NC 令牌共用编解码管线，但保留电路专用校验 |
| NC 流体 | 默认拒绝，理由为 `NON_CONSUMABLE_FLUID_UNREPRESENTABLE` |

### 7.3 安全校验

1. 解包物品必须在目标缓冲区的虚拟槽位中可容纳。
2. 令牌的包装物品与规则生成时的候选必须一致。
3. 不能包装、不能序列化或不允许进入虚拟槽位的物品必须拒绝。
4. 令牌展开后的输入数和缓冲区槽位数必须同时满足 AE2 与 GT 的上限。

## 8. 可组合规则引擎

### 8.1 设计原则

规则引擎不是“JSON 权重表”。它应当在统一事实模型上执行布尔约束、标签归类、分数修改、候选数量、循环策略、输出策略和解释记录。

规则执行分两层：

1. **规则数据包**：决定大多数整合包策略，例如配方表优先级、材料路线、回收策略、循环断点和输出策略。
2. **Java 适配器 SPI**：把 GT 或第三方模组难以静态描述的能力、属性和谓词暴露为规则事实。适配器提供事实，不直接替用户做路线决策。

### 8.2 规则层级与冲突解析

规则层级从低到高为：

```text
核心默认规则
  < 模组适配规则
  < 整合包全局规则
  < RecipeMap / 配方分类规则
  < 控制器类型规则
  < 单个样板总成规则
  < 管理员固定或禁用路线规则
  < 不可绕过的安全规则
```

冲突解析必须固定且可解释：

| 效果类型 | 合并方式 |
| --- | --- |
| 硬拒绝 | 任意命中即拒绝；安全拒绝不可由高层覆盖 |
| 允许 | 仅能解除普通默认拒绝，不可解除安全拒绝 |
| 标签 | 去重并集 |
| 数值分数 | 按规则优先级顺序累加或乘算，计算过程记录在解释中 |
| 标量策略 | 最高优先级规则获胜，同优先级按规则 ID 稳定排序 |
| 候选上限 | 取最严格安全上限与策略上限的交集 |
| 固定路线 | 只在通过全部硬约束后生效 |

### 8.3 规则谓词

规则条件至少支持：

- RecipeMap ID、RecipeMap 标签、配方分类、来源模组。
- 目标物品/流体、材料、矿辞前缀、NBT、物品标签。
- 输入中的材料关系，例如“含非目标材料”“仅为目标材料形态转换”。
- 确定性输出、隐藏输出、随机输出和净产出。
- GT 配方属性及其值域。
- 控制器能力、维度、洁净室、线圈、温度、计算量、能量门槛和输出能力。
- 库存存在性、库存量区间、外部资源种子标记。
- 当前路线深度、已访问节点、循环分量、是否处于最优重建。

条件组合支持 `all`、`any`、`not`、比较、集合匹配和命名谓词。

### 8.4 规则效果

规则可以产生以下效果：

```yaml
effects:
  - deny: UNSUPPORTED_PROPERTY
  - requireCapability: cleanroom
  - tag: route.chemical_synthesis
  - tag: cycle.external_seed
  - score: { routePriority: 800, rawMaterialWeight: 0.8 }
  - penalize: { hiddenOutputWaste: 300 }
  - expose: { maxPatternsForTarget: 2 }
  - outputPolicy: DETERMINISTIC_ONLY
  - cyclePolicy: BREAK_AT_EXTERNAL_SEED
  - pinGroup: polymer.primary
```

### 8.5 第三方属性与适配器

所有未知 `RecipeProperty` 默认产生 `UNKNOWN_RECIPE_PROPERTY` 拒绝。适配器可注册：

```java
interface RecipePatternFactContributor {
    void contributeRecipeFacts(Recipe recipe, RecipeFacts.Builder facts);
    void contributeMachineFacts(MultiblockControllerBase controller, MachineFacts.Builder facts);
}

interface RecipePatternConstraint {
    RuleDecision evaluate(NormalizedRecipe recipe, MachineCapabilityProfile machine, PlanningContext context);
}
```

适配器不能绕过核心的输出安全、精确绑定和线程安全检查。

## 9. 路线层的数据驱动深度改造

### 9.1 从硬编码优先级迁移

当前“化学合成、粉末/流体、锭、普通、形态转换、回收”等固定枚举只保留为默认规则包中的标签和初始权重，不再由核心代码决定最终优先级。

核心路线层只负责：

1. 建图。
2. 应用硬约束。
3. 执行规则并收集标签和代价。
4. 在预算内搜索候选。
5. 根据规则产生的多维成本和固定 tie-breaker 排序。

规则包决定“什么是优先路线”。例如，聚合物化学合成优先于粉末回收、特定裂化路线禁止作为原料链、某个深度魔改机器只能走指定反应路径，都应写成规则而非改动核心 Java 分支。

### 9.2 配方依赖超图

对于每个 `TargetedRecipe`，建立一条超边：

```text
{输入 A, 输入 B, NC 令牌 C} --[配方绑定 / 规则标签]--> 目标 T
```

隐藏的实际输出不构成 AE2 可满足的依赖边，但会附着在边的输出容量和浪费成本上。一个目标节点可有多个候选超边。

### 9.3 多维成本而不是单一优先级

候选路线成本使用字典序向量，默认维度为：

1. 硬约束状态。
2. 固定路线或禁止路线。
3. 路线组优先级。
4. 当前库存可直接满足程度。
5. 外部原料消耗估算。
6. 依赖步骤数与图深度。
7. 能耗、时长、吞吐能力和并行限制。
8. 隐藏副产物的堵塞、浪费与清理代价。
9. 循环风险和循环断开代价。
10. 稳定配方指纹，用于完全确定的最终 tie-breaker。

规则可对任意维度加权、封顶、强制分组或固定选择。规则不能修改“硬约束先于成本”的顺序。

### 9.4 Pareto 候选与样板暴露

对每个目标先保留受预算限制的 Pareto 前沿，而不是立即只留一个候选。例如：

- 路线 A：库存充足、材料成本高。
- 路线 B：库存不足、原料成本低。
- 路线 C：吞吐高、隐藏副产物风险高。

默认生产模式可只物化 1 条样板，整合包或 RecipeMap 规则可将 `maxPatternsForTarget` 提高为 2 至 N。无论物化几条，每一条仍是单目标样板。

### 9.5 规划模式

规则可选择不同的路线配置文件：

| 模式 | 主要目标 |
| --- | --- |
| `STOCK_FIRST` | 优先使用当前网络已有物料 |
| `RESOURCE_FIRST` | 优先降低外部原料总量 |
| `THROUGHPUT_FIRST` | 优先可并行、低时长、高吞吐路线 |
| `SAFE_FIRST` | 严格回避隐藏产物、随机结果和复杂循环 |
| `PINNED` | 使用管理员或总成固定的路线组 |

最优重建按钮可明确使用 `RESOURCE_FIRST` 或规则指定的 profile；普通 AE2 请求默认使用 `STOCK_FIRST`。

## 10. 循环路线处理

### 10.1 基本策略

循环不能依赖“执行失败后不断删除样板”作为主要机制。新系统需要在图规划阶段检测循环，并把运行时恢复保留为最后一道防线。

每个候选边具有循环角色：

| 角色 | 语义 |
| --- | --- |
| `EXTERNAL_SEED` | 允许作为依赖终点，例如矿物、外部供应、库存种子 |
| `ALLOW_NET_POSITIVE` | 仅当目标净产出为正且存在外部输入时允许 |
| `BREAKABLE` | 进入循环时优先移除或高惩罚该边 |
| `PENALIZE` | 可保留但增加循环成本 |
| `FORBID` | 不允许进入动态路线图 |
| `RECYCLE_ONLY` | 只能作为回收末端，不能反向充当原料源 |

### 10.2 强连通分量规则

1. 对当前请求可达的动态路线图计算强连通分量（SCC）。
2. 每个被选中的 SCC 必须能到达至少一个 `EXTERNAL_SEED`、真实库存物料或普通静态样板叶节点。
3. 仅靠本 SCC 内部转换就能“制造”目标的路线必须拒绝。
4. 当多个断点可选时，优先保留库存可满足、外部原料可达、非回收和净产出更高的边。
5. 已知反向形态转换、回收回路和材料自循环由规则包标注，而不是只依赖材料名前缀猜测。

### 10.3 运行时防线

AE2 规划过程中仍可能因其他静态样板或并发变更形成未预测循环。此时保留现有递归恢复机制，但改为按 `RecipeBinding` 和规则原因记录拒绝，避免把无关的同目标候选一并删除。

## 11. 精确执行绑定

### 11.1 新接口

在现有 `IRecipeMapBoundInput` 之外新增概念接口，例如：

```java
interface IRecipeBoundInput extends IRecipeMapBoundInput {
    @Nullable RecipeBinding getRecipeBinding();
}
```

隔离缓冲区 handler 实现该接口。`MultiblockRecipeLogic` 的查找流程在收到此类输入时：

1. 验证绑定的 RecipeMap 仍属于该控制器可路由集合。
2. 使用当前 RecipeMap 内容版本解析指纹到唯一 `Recipe`。
3. 用缓冲区实际输入再次执行 `Recipe.matches(...)`。
4. 运行控制器的只读可执行性检查。
5. 只有全部通过才返回该精确配方；不得退化为同 RecipeMap 的任意匹配配方。

### 11.2 缓冲区签名与持久化

`BufferSignature` 需要从：

```text
inputs + patternKey + recipeMapName
```

升级为：

```text
inputs + recipeBinding + NC token layout + normalizationVersion
```

缓冲区 NBT 与动态样板缓存都要增加版本号。旧版本数据在加载时只允许安全丢弃并请求重新生成，不能尝试猜测新的精确绑定。

### 11.3 执行失败

以下情况必须拒绝推送或停止执行并输出明确原因：

- 配方已被脚本、重载或版本更新移除。
- 指纹解析到零条或多条配方。
- 当前控制器能力已不满足属性要求。
- 目标输出、隐藏输出或输入容量无法满足。
- NC 令牌解包结果与绑定不一致。

## 12. 索引、缓存与性能预算

### 12.1 分层缓存

| 缓存 | 键 | 失效条件 |
| --- | --- | --- |
| RecipeMap 输出索引 | RecipeMap 内容版本 | 配方表重载、数量或指纹变更 |
| 规范化配方缓存 | RecipeBinding | 规范化版本或 RecipeMap 内容变更 |
| 能力过滤缓存 | Binding + MachineProfile 版本 | 结构、能力、规则或控制器状态变更 |
| 候选路线缓存 | 目标 + 规则版本 + profile | 库存策略、规则、图依赖变更 |
| 已物化样板缓存 | TargetedRecipe 指纹 | 上述任意相关缓存失效 |

### 12.2 预算

默认预算必须可通过规则配置调整：

- 每目标候选配方扫描上限。
- 每目标保留的候选数量与 Pareto 上限。
- 最大图深度、最大边扩展数、最大 SCC 分析范围。
- 单次路线计算时间预算。
- 单个 Provider 持久化样板上限。

达到预算时不应 silently 选择不完整结果；应记录 `BUDGET_EXHAUSTED`，并按规则选择“保守拒绝”或“明确降级候选”。

### 12.3 并发与失效

1. 异步规划只读取不可变快照。
2. Provider、规则与 RecipeMap 的变化增加 epoch，不直接修改正在使用的快照。
3. 已提交 CPU 持有的旧样板保留到任务结束，但新请求不得使用失效绑定。
4. 规则重载必须原子切换 RuleSet 版本，并使相关候选缓存失效。

## 13. 日志、诊断与 GUI

日志是该系统的必要功能，而不是调试附属物。所有日志应使用 `ApplyGrayMod.LOGGER`，并按等级控制噪声。

### 13.1 结构化事件

每个事件至少带有：

```text
providerId, position, dimension, target, recipeMapId, recipeFingerprint,
ruleSetVersion, planningMode, decision, reasonCode, elapsedMs
```

| 级别 | 事件 |
| --- | --- |
| `DEBUG` | 候选筛选、命中规则、循环边选择、NC 令牌展开 |
| `INFO` | 规则重载、索引重建、最优重建汇总、缓存迁移 |
| `WARN` | 预算耗尽、失效绑定、输出容量风险、未知属性、精确执行不一致 |
| `ERROR` | 不可恢复的绑定解析错误或序列化错误 |

### 13.2 诊断视图

配方表样板总成和样板访问终端应能查看：

1. 当前可路由的 RecipeMap 与 MachineProfile 摘要。
2. 一个目标的候选路线、被拒绝路线和原因。
3. 已物化样板的精确绑定、目标产物和隐藏实际产物摘要。
4. 命中的规则 ID、成本向量、循环断点和预算状态。
5. 清理缓存、重新评估规则和执行最优重建的安全操作。

## 14. 配置与规则包

建议目录结构：

```text
config/applygray/recipe-pattern-rules/
  defaults.json
  gregtech.json
  pack-overrides.json
  controllers/
  recipemaps/
  providers/
```

规则加载必须提供：

- JSON Schema 校验。
- 重复规则 ID、循环引用、未知谓词和未知效果的启动期错误。
- 规则优先级和最终合并结果的日志摘要。
- 可选热重载；热重载失败时继续使用上一份有效 RuleSet。
- `unsafe` 规则必须显式开关并在日志中警告。

## 15. 实施拆分

### 阶段 A：语义与绑定基础

1. 引入 `NormalizedRecipe`、`TargetedRecipe`、`RecipeBinding` 与版本化序列化。
2. 保持单目标输出，补齐隐藏实际产物元数据与输出容量检查。
3. 实现 NC 物品的可编程电路令牌展开。
4. 让缓冲区与执行逻辑支持精确绑定，禁止同表任意配方回退。

### 阶段 B：机器能力与硬约束

1. 建立 `MachineCapabilityProfile` 主线程快照。
2. 接入 GT 内建 RecipeProperty 适配器。
3. 建立未知属性的保守拒绝、理由码和日志。
4. 将输出容量、随机产物、NC 令牌容量纳入硬约束。

### 阶段 C：规则引擎与路线图

1. 实现 RuleSet、层级合并、谓词、效果和解释链。
2. 将现有材料启发式迁移为默认规则包。
3. 实现超图候选、Pareto 前沿和多规划模式。
4. 实现 SCC 循环约束和运行时回退防线。

### 阶段 D：运营与兼容性

1. 完成缓存 epoch、规则重载、指标和诊断 GUI。
2. 升级 NBT 版本并安全迁移或丢弃旧缓存。
3. 为大型配方池建立性能基准和回归样例。
4. 分批启用：默认保守模式、白名单 RecipeMap、整合包规则包、全面启用。

## 17. 测试策略

### 17.1 单元测试

- 单目标化：主产物、副产物、输入回流、流体输出、NBT 敏感输出。
- 随机输出：确定性目标允许、随机目标拒绝、保证下限适配。
- NC 令牌：单个、多个、替代项、NBT、槽位不足和非法包装。
- 规则：层级优先级、冲突解析、未知属性、固定路线、候选上限。
- 绑定：指纹稳定性、碰撞检测、RecipeMap 重载、同表同输入歧义。
- 循环：直接循环、三节点循环、回收环、带外部种子的正净产出环。

### 17.2 集成测试

- 模拟 AE2 请求并验证只获得单目标样板。
- 将样板推入缓冲区，确认 NC 电路被消耗且内部物品正确解包。
- 验证多 RecipeMap 多方块仅执行绑定配方。
- 验证能力变化、规则重载和配方重载后旧样板不会被新请求使用。
- 验证隐藏副产物导致输出堵塞时样板被拒绝。

### 17.3 性能测试

至少覆盖：数万至数十万配方、一个目标数百条候选、多 Provider、多 RecipeMap、深度依赖链和大循环分量。指标包括索引时间、单目标 p95 规划时间、内存占用、缓存命中率、预算耗尽率与重建耗时。

## 18. 验收标准

完成后必须满足：

1. 每个动态样板只向 AE2 声明一个确定性目标产物。
2. 同一物理配方的任何确定性副产物均可作为独立目标样板生成。
3. 所有可表示 NC 物品使用“AE2 消耗电路令牌、缓冲区解包原物品”的统一语义。
4. 动态样板在执行时命中生成阶段选定的精确配方，绝不回退到同表任意匹配配方。
5. GT 内建属性与已安装适配器声明的第三方属性都参与可执行性判断；未知属性默认拒绝并有理由码。
6. 路线规则可由数据包定义、组合、覆盖和解释，不需要为整合包策略修改核心候选排序代码。
7. 循环路线在规划阶段被识别并按规则处理，运行时恢复仅作为防线。
8. 所有预算耗尽、拒绝、失效绑定和不一致执行都有可定位日志。
9. 配方表重载、控制器能力变化和规则重载后，缓存不会产生过期样板。
