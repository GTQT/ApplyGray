# 物质操纵器完整移植规格

## 1. 目标与完成定义

本文档是 `D:\mc\modgit\MatterManipulator` 到 ApplyGray 的完整功能概念与视觉资源移植合同。源项目基准为提交
`46cbd327d97fd78429f5e5e7d176206d01e7e02a`，目标环境为 Minecraft 1.12.2、Cleanroom、Java 25、
ApplyGray 当前使用的 GregTech 与 Applied Energistics 2 Supergiant。

“完整移植”不表示逐行复制 1.7.10 实现，而表示以下四类结果同时成立：

1. 玩家可以在生存模式中取得、配置、供能和使用四级物质操纵器。
2. 原项目公开描述的建造模式、变换、资源来源和机器复制语义在目标 API 上具有明确等价实现。
3. 四把工具、28 个组件/升级，以及量子上行链路的原始视觉资产均有目标物品、模型或机器渲染入口。
4. 注册、模型、配方、服务端执行、客户端预览、AE/GT 适配均通过对应的自动化与游戏内验收。

编译、单元测试或 jar 中存在类文件只能证明一个阶段可构建，不能单独把任何功能标记为“已验证”。

## 2. 架构边界

- 所有世界修改、资源扣除、EU 扣除、权限检查和机器状态应用均由服务端决定。
- 客户端只发送手势、模式选择和物品选择等意图；服务端从玩家手中工具的 NBT 读取权威状态。
- 普通方块、GregTech 和 AE2 使用独立 `BuildingAdapter`。未知 TileEntity 必须明确拒绝，不能回退到裸 TileEntity NBT 克隆。
- 移动模式也必须使用目标适配器的可逆捕获/应用事务；不得保留源项目的任意 NBT 搬运兼容路径。
- AE2 适配仅通过 ApplyGray 代码和 Mixin 完成，不修改 AE2 Supergiant 源码。
- 不保留源项目 1.7.10 的旧包名、旧网络包、旧 GUI API 或兼容接口。目标注册名统一使用 `applygray:*`。
- 批处理日志只记录开始、结束、取消和首次失败，不在每方块或每 tick 输出日志。

## 4. 交互合同

目标交互保留原项目的动作概念，同时使用 1.12.2 输入与网络 API：

- 手持工具对空气右键：打开配置界面。
- 对方块右键：按当前待处理动作标记 A、B 或 C；潜行时选择命中的方块，否则选择命中面外侧。
- `Ctrl+X`：切换移动模式并开始标记剪切区域。
- `Ctrl+C`：切换复制模式并开始标记复制区域。
- `Ctrl+V`：标记粘贴原点。
- `Ctrl+Z`：清除坐标和变换。
- 中键：按当前配置动作拾取几何材料、交换筛选/替换材料或线缆。
- 几何模式首次进入时中键目标必须为“全部”：普通中键用同一方块覆盖角/边/面/体四个列表，潜行中键向四个列表追加一个加权候选。只有从配置界面明确选择角、边、面或体后，才只修改单个角色。
- 潜行右键持续 10 tick：开始执行；松开或切换物品会取消蓄力。再次执行键可取消已开始的批处理。
- 早期重写使用的 `M` 配置与 `B` 执行入口已删除；目标实现不注册这两个旧入口。

所有按键必须出现在控制设置中，并且只在手持 `ItemMatterManipulator` 时处理。客户端输入触发一次动作时，服务端只接收一个意图包。

### 4.1 配置界面视觉与交互合同

配置界面不是背包槽列表。目标必须复刻源项目的两层 UI：

1. 主界面为透明全屏放射菜单，中心显示 32×32 的当前工具；内半径为屏幕短边的 0.25，外半径为 0.60；可见项等分整圆并把首项旋转半个扇区；普通扇区为黑色，悬停为 25% 灰；标签按 60 px 宽度换行并居中。
2. 点击分支时与源实现相同，原地替换为子扇区且不保留父菜单历史；Esc 关闭界面。叶子动作关闭界面回到世界；“编辑变换”例外，进入第二层透明全屏界面。
3. 根菜单包含按等级隐藏的模式、移除策略，以及当前模式的几何材料/形状/坐标、复制/移动、交换、线缆和上行链路规划分支。
4. 复制变换界面左侧提供绕 X/Y/Z 正负 90 度、X/Y/Z 镜像、坐标轴摘要和重置；右侧提供复制区域整体平移、A/B/C 三轴坐标、X/Y/Z 堆叠次数。每一轴按源 UI 使用 40 px 减按钮、40 px 数值框、40 px 加按钮；Shift 步进 10，Ctrl 按选区轴长步进。移动变换界面提供 A/B/C 坐标、区域整体平移和区域交换。GUI scale 不大于 2 且高度足够时使用源实现的单列，其他情况拆成右侧双列以防越界。
5. 三维变换必须由同一个正交整数矩阵同时作用于规划坐标、普通方块朝向/轴属性、GT 机器正面/管线连接和 AE2 部件/Facade 侧面。方块无法表示变换后的朝向时明确拒绝，不得静默保留旧朝向。

## 5. 等级、能力与升级

| 等级 | 范围 | 电压级 | 容量 | 基础能力 |
| --- | ---: | ---: | ---: | --- |
| 原型 MK0 | 32 | HV | 10,000,000 EU | 几何；安装采掘后允许移除 |
| MK I | 64 | EV | 100,000,000 EU | 几何、移除、交换、线缆、AE 材料来源 |
| MK II | 128 | IV | 1,000,000,000 EU | MK I + 复制、移动 |
| MK III | 无限制 | LuV | 10,000,000,000 EU | MK II + 上行链路、智能复制 |

升级概念：

- 能量隧道：允许 MK III 从量子上行链路取得远程供能。
- 采掘：允许原型移除方块。
- 辅助传送器：提高批次大小/缩短批次间隔。
- 自适应线束：把每次操作 EU 消耗降低 50%。

升级合成必须保留工具现有 NBT、电量和已安装升级，拒绝重复或等级不允许的升级。

## 7. 生存合成链

不再由最终工具直接消耗少数组件。每一级必须先制造五类分级组件，再组装对应工具；高一级工具组装必须消耗前一级工具，保留其 NBT 和电量的升级配方另行处理。

目标配方链：蓝图 -> MK0 五组件 -> MK0 -> MK I 五组件 -> MK I -> MK II 五组件 -> MK II -> MK III 五组件 -> MK III。ME/量子下行链路、空白升级和四种升级均必须有独立配方。具体材料使用目标 GregTech 已存在的电路、场发生器、传感器、发射器、电机和高阶材料，不引用 1.7.10 数值 ID。

配方注册必须检查 `ValidationResult`；任一必需配方无效或冲突时，以启动期一次性错误记录注册名，不能静默跳过。

## 8. 方块与机器状态复制合同

### 8.1 普通方块

- 方块状态、方向和安全可序列化的公开属性。
- 普通容器内容按真实物品转移；复制目标必须额外消耗这些内容，移动则保持总量。
- 矿石被移除时不得产生矿物掉落套利；按目标平衡策略拒绝或仅回收对应方块物品。

### 8.2 GregTech

当前适配器的可执行合同是：

- 空机器：物品形态公开数据、正面、染色和自定义名称；智能复制模式额外允许明确实现
  `ISmartCopyLinkable` 的机器只保存源链接。
- 空管道/线缆：材料/规格、染色、各面连接、各面阻断状态和框架材料。
- 有真实物品、流体、额外掉落或无法由公开物品/API 重建的机器一律拒绝，不做免费 NBT 克隆；覆板逐面保存物品、定义和配置数据，幽灵电路保存标准电路或自定义物品并在目标重新配置。
- 自动输出、工作允许、批处理、输入分离、总线/仓锁定及任意 `IDataCopyable` 数据尚未纳入当前捕获结构，不能宣称已复制。

### 8.3 Applied Energistics 2

当前适配器的可执行合同是：

- CableBus 以中心线缆、各侧部件和 Facade 为一个捕获/恢复单元；带有无法安全消费的库存型掉落时拒绝。
- Pattern Provider 的普通复制按真实样板/升级物品计入事务，恢复到对应槽位；目标槽位变化时失败并回滚。
- Smart Copy 只保存源维度、CableBus 坐标和侧面，借用源样板发布，不复制源升级或物品库存。
- 其他 AE2 单方块机器、存储元件及未在 `Ae2BuildingAdapter` 中显式支持的配置拒绝，不回退到 TileEntity NBT。
